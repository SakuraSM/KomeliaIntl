# Reader issues 74 and 62

## Scope and result

Base: `v0.27.0-beta.3`, commit `265f62d8`. Branch: `fix/reader-74-62`.

- #74: mode hints belong to a reading session and explicit mode/direction changes. Rotation retains the saved marker; actual reader exit clears it. Re-selecting the current value still saves the preference without showing a duplicate hint.
- #62: fixed the confirmed continuous-reader over-rendering path. The first visible page previously requested its entire remaining length. Requests now cover the scroll-axis viewport, with right-origin RTL coordinates and trailing page spacing accounted for. The first image after a header and the partial last RTL image follow the same rule.
- This is not a full resolution of #62. Sustained panel blur was not reproduced with the tested model and pages. No speculative panel-renderer or cache-budget changes were made.

## Automated evidence

- The extracted original hint effect failed all three initial `ReaderModeHintEffectTest` scenarios. The fixed effect passes initialization, recreation, explicit-request and new-session checks. A fourth test exercises actual saveable-state restoration.
- `ReaderSiblingStateTest` confirms that a repeated current-mode choice still writes the preference and does not issue another hint request.
- The old first-page viewport calculation failed the long-page, horizontal-window and invalid-dimension tests. Additional RTL tests caught the left-origin mistake before its correction. Six viewport tests now cover vertical, LTR, RTL, partial entry, spacing, image ends and transient dimensions.
- Final UI tests: JVM 210 and Wasm browser 153 passed. Core tests: JVM 6 and Wasm browser 5 passed. Total: 374, with no failures or skips in those suites.
- Final `androidDebug desktopJar komfWebUI` matrix passed with the affected tests. The final run completed in 3m43s, 533 tasks. Desktop build and browser tests are not desktop GUI acceptance.
- Harness checks and 22 Node tests passed, including the regression runner and synthetic server checks.

## Device evidence

Dedicated arm64 emulators: `Komelia_Regression_API35` and `Komelia_Regression_API37`, 1080x2400 portrait and 2400x1080 landscape, English UI. No production installation or private server was used.

- Baseline rotation showed the mode toast again. Screenshot `old-rotation3.png` and OCR recorded `Continuous` and `Top to bottom`.
- Each emulator performed ten portrait/landscape cycles on the delivered APK. All 40 transitions reached the expected orientation without replaying a mode hint. Screenshots and OCR results are under `rotation-emulator-5564` and `rotation-emulator-5562`.
- API37 synthetic three-page comic retained page 2 after rotation. Explicit direction change showed `Paged / Right to left`; repeated selection did not show another hint. Exit and reopen showed the initial hint again after the navigation-state fix.
- Original webtoon: observed transient blur during fast movement and excessive background work on the baseline. A landscape page-2 render generated 1640 tiles and took about 9.6 seconds. Bounded-window runs generated tens of tiles and completed below one second in the recorded positions. These are diagnostic observations, not a controlled device-performance benchmark or a guarantee for the reporter's phone.
- Slow, fast and reverse vertical scrolling, stopping and rotation were exercised on the original webtoon. Clear image output and foreground completion logs were checked together.
- Original CBR: RF-DETR Nano ran real detection; counts 0/1/2 were selected and same-page/cross-page navigation exercised. Logs include `reused pre-rendered viewport` at count 1. The final spacing/session-only adjustments did not modify the panel renderer; the full panel sequence was not repeated after those final adjustments.
- RTL and page-spacing coordinate cases are covered by automated regression, not a claim of exhaustive horizontal device acceptance.
