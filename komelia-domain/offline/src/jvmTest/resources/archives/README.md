# Synthetic archive fixtures

These Base64 fixtures contain only generated text. The Android instrumented tests use identical copies in their test assets. Reporter archives are never stored here.

- `solid-lzma.7z.b64` contains `one.txt` with `synthetic first entry` and a newline, and `two.txt` with `synthetic second entry` and a newline. It was generated with `bsdtar --format 7zip -cf solid.7z one.txt two.txt`. Both entries share one LZMA folder, which was verified from the archive metadata. The tests read them in reverse order through the converted cache.
- `stored-rar4.rar.b64` is a generated RAR 4 stored-entry archive. It contains `chapter/1.png` with `synthetic rar page` and a newline. This is intentionally text, not a rendered image. Its main, file and end headers carry CRCs; the end header uses the standard skip-if-unknown flag. It tests archive routing and entry bytes without an external RAR tool.

COPY, LZMA and LZMA2 fixtures are generated by `SevenZOutputFile` inside the tests. Unsupported-method and encrypted-entry fixtures modify a generated COPY coder descriptor and recalculate the header CRCs. Tests exercise the real decoder rather than substituting thrown exceptions for these cases.
