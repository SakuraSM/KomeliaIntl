## EPUB 章末接续

原有 Komga EPUB 阅读器选择未改变。原有布局为分页，本次使用应用的 `v` 快捷键切换到滚动布局后验证，未将分页模式下的垂直拖动计作失败。

关键场景通过：

- 短章初始进入后停留，不自动跳到下一章。
- 1100 ms 慢拖从第 1 章进入第 2 章，从第 2 章顶部反向慢拖返回第 1 章。
- 长章内部从偏移 1000 滑到约 1294 CSS 像素，保持第 2 章，不提前切章。
- 长章靠近底部时，100 ms 快滑抬手后依靠惯性进入第 3 章，无需第二次手势。第 3 章停留后不继续连跳。
- 触摸记录包含 `isTrusted=true`，不是构造 JavaScript TouchEvent 或调用阅读器切章方法代替输入。

惯性场景的实际记录：起始偏移 `10640`，章末 `10940`，抬手偏移 `10889.9043` CSS 像素。抬手尚距章末约 50.1 像素，之后章标题变为第 3 章，偏移归零。

WebView 调试接口用于观测章标题、安装事件记录器，以及准备合成章节的起始滚动位置。跨章动作由手机系统触摸输入触发。

双指与取消手势最终通过临时原生辅助测试。使用 `UiAutomation.injectInputEvent` 注入两指移动及单指拖动后的 `ACTION_CANCEL`，断言注入成功、页面收到可信事件，以及短章没有误跳。最终记录 23 个触摸事件，最大指针数 2，全部 `isTrusted=true`，包含 1 个取消事件，章标题始终为第 1 章。两指事件在外层文档，取消事件在 iframe，不能只观察 iframe 来判断是否收到两指输入。

最后一次组合运行结果为 `OK (3 tests)`，其中分享 2 项、原生双指与取消 1 项。前期安装完成页遮挡、Compose 节点定位失败、仅观察 iframe 漏报的记录全部保留，没有计作成功。临时测试辅助源码和 APK 已保存在忽略的 QA 目录，不加入默认回归套件。

## 原始长图模糊对照

两个包使用同一份原始 CBZ，本地文件来源、连续从上到下模式、0% 侧边距、Lanczos3 放大、Mitchell 缩小及单书关闭颜色校正。保留原有裁边设置。

从第 1 页开始，连续点击向前区域 8 次，间隔约 90 ms 加系统输入调用耗时。停手后不再操作，保存 0、2、5、20 秒的截图。另做快速前滚、反向滚动和停留检查。

| 观察 | 对照包 | 修复包 |
|---|---|---|
| 快速操作后 | 出现低清预览 | 也可出现低清预览 |
| 第 1 页连续点击后的 2 秒截图 | 仍低清 | 已清晰 |
| 5 秒及 20 秒 | 恢复清晰 | 保持清晰 |
| 快速前后滚动后停留到 20 秒 | 恢复清晰 | 恢复清晰 |

这只是本轮离散截图观察，不是恢复时间的精确测量或性能统计。截图采集本身约需 0.8–1.3 秒，停止滚动后位置也会随动画收敛。不能用单轮截图差异宣称固定性能提升。

修复包另完成一次横屏和竖屏切换，取得对应画面，最终恢复竖屏。该检查不替代所有方向、页码和缩放比例的完整验收。

两包均未完整复现“停留后一直模糊，必须再操作才清晰”。因此 #62 仍为部分验证，不判定完全修复或关闭。分镜和 ONNX 场景未覆盖。
